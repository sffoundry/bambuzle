# BAM-16 review: accounts & roles (1c06933..bd2d70c)

An independent review agent probed an isolated server on an ephemeral port with probe scripts. It found 2 high, 3 medium and 7 low issues. All are fixed with regression tests in `test/users.test.js` ("review #N"), and the full suite passes 167/167.

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| 1 | High | Parallel wrong-password burst got past the lockout (40 parallel → 40×401) | `src/server/login-limiter.js` reserves the attempt before the scrypt check and releases it on success |
| 2 | High | Last-admin guard race: an `await hashPassword` sat between the check and the UPDATE, so two concurrent demotions left 0 admins | Hash first, then check + UPDATE in one synchronous `db.transaction()` |
| 3 | Med | WebSocket not re-checked after disable/delete/sign-out | `revalidateClients()` re-runs the upgrade check (fresh session lookup); called after account changes and sign-out, plus a 30 s sweep |
| 4 | Med | Anyone could keep any account (all admins) locked via the per-username limit | A client IP that signed in successfully as that user in the last 30 days is exempt from that user's lock (the per-IP limit still applies) |
| 5 | Med | `disabled: "false"` disabled the user | Must be a boolean, otherwise 400 |
| 6 | Low | Login CSRF / forced sign-out: `/api/session` sits before the guard | The same-host Origin check now also applies to session POST/DELETE |
| 7 | Low | Typed username (possibly a pasted password) stored in the audit trail | Recorded only when the username exists |
| 8 | Low | Duplicate-create race → 500 | UNIQUE constraint → 409 |
| 9 | Low | No limit on `/api/me/password` current-password guesses | 5 per user per 5 min, then 429 |
| 10 | Low | Lenient ids (`" 1 "`, `0x1`, `1e0`) | Strict `^[1-9]\d*$` |
| 11 | Low/Med | Viewer/operator stuck on the BambuLab Cloud login when the server has no cloud session (only admins can sign in to cloud) | Non-admins skip the cloud overlay; browser-verified |
| 12 | Low | UI defaulted to admin role until `/api/session` resolved | Defaults to viewer (`dashboard.js` + `<html data-role="viewer">`) |

Not changed:
- `/metrics` is readable by any signed-in role. This is intended.
- X-Forwarded-For spoofing only matters with `BAMBUZLE_TRUST_PROXY` set and no proxy in front; that is a config issue documented in Install.md.
