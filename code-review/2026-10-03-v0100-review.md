# v0.10.0 review: camera capability (BAM-35) + power tracking (BAM-18), 48e221a..0c78704

An independent review agent probed 127.0.0.1 fakes only. It found 0 high and 5 confirmed issues (1 medium, 4 low), plus several plausible ones. It found no secret leak and no authz gap. All confirmed issues are fixed, with regression tests in `test/power.test.js` ("review #N"). The full suite passes 186/186.

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| 1 | Med | A password in the plug URL never worked, because Node `fetch` rejects `user:pass@` URLs. Password-protected Shelly Gen1 and Tasmota plugs were unreadable | Credentials are moved out of the URL: HTTP Basic for Shelly Gen1 and generic plugs, `user`/`password` query parameters for Tasmota. Shelly Gen2+ (Digest auth) is documented as unsupported |
| 2 | Low | A restart overwrote the energy already recorded for the current minute | The first bucket after start-up resumes the stored row |
| 3 | Low | Back-to-back jobs both counted the shared minute, and idle draw before the start was billed to the job | Boundary minutes are prorated by how much of them the job window covers |
| 4 | Low | `url: [..]` (an array) passed validation | Plug fields must be strings (PUT and test) |
| 5 | Low | A body that stalled past the timeout escaped as a raw DOMException. Error responses never released their body | The body read is wrapped as a PlugError, and the body is cancelled on 3xx, 401 and non-OK responses |

Fixed from the plausible list:
- `currency: null` now clears the currency.
- Removing a circuit's limit now re-arms its alert.

Accepted / not changed:
- **Admin-only "numeric oracle" via the http-json test:** same scope as the existing LAN connection test.
- **A re-arm during the rule's cooldown can be missed:** shared with the AMS humidity rule; noted for an alert-engine pass.
- **`cameraMonitor.forget()` is not called on printer delete:** a tiny in-memory entry.
